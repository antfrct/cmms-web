Main missing features

  • Automatic work-order generation from maintenance plans — today only simulated (§13)
  • Pagination on every list (§2.3)
  • Asset photo, commissioning date, Preventive tab, decommission / delete (§6, §7)
  • Bulk QR printing, PNG download, label formats; QR encoding the asset URL (§8)
  • Asset import and export (§7.2)
  • Home: priority alerts, calibration / control reminders, operational KPIs, period selector (§4)
  • Create a work order from a Planning slot (§11)
  • Type › Sub-type taxonomy (§1)
  • Meter readings, condition-based triggers, RCA / FMEA (§1)
  • Alert rules per asset / owner and recurring-failure detection (§17)
  • History / audit trail on work orders and assets; sign-in screen (§19, §4)

Quick wins

  • “?” help icon in the top bar; red asterisks on every form; menu labels “Preventive” and “Administration”
  • Activate the Improvement type; add a Sub-types list per type in Site configuration
  • Assets: status KPI strip, row checkboxes, Export (reuse the Work orders export)
  • Asset photo (reuse the Spare parts image upload) and commissioning date
  • QR dialog: Download PNG + label-format presets
  • Work orders KPI “In progress”; “Create another” on the wizard's last step
  • Planning KPI strip; Documents: rename Drawing → Plans
  • Home alert cards — all the data already exists

Major gaps

  • 5-level asset breakdown: Machine › Sub-assembly › Component under an asset (§5)
  • Condition-based maintenance: measurement points, reading history, thresholds (§1)
  • Root-cause analysis / FMEA records (§1)
  • Asset import with column mapping and validation (§7.2)
  • Configurable alert rules and recurring failures (§17)
  • Cross-module even if each piece is simple: plans → work-order generation feeds Planning, Home, Asset Detail and notifications (§13)

Conflicts with the current design

  • Work orders called “Interventions” — in Relix, Intervention is the execution mode (§2.1)
  • Overdue and “Waiting for parts” as statuses — Relix: derived state + Waiting flag; spec lacks Requested (§9)
  • Assignee mandatory at creation — Relix allows unassigned requests and assigns by skill per checklist part (§10)
  • Spare parts deferred to V2 — checklists, Waiting, closure and costs depend on it (§4)
  • Linear checklists only — Relix typed steps and workflow drive assignment, parts, tools and costs (§12)
  • Dropping the notification centre — breaks mentions and reassignment requests (§21)

Priorities

  1. Settle the 6 conflicts with the spec authors — vocabulary, status model, mandatory assignee, Spare parts scope, checklist scope, notification centre. Decisions, not code, but they shape everything else.
  2. Make preventive real — shared plans model + generation into the work-order store. Unlocks Planning, Home alerts and reminders, the Asset Detail Preventive tab and due-soon notifications.
  3. Fix the asset hierarchy depth (5 levels vs. Zone › Line › Step › Asset) before building Import — the import format depends on it.
  4. List mechanics across modules — pagination, row selection, export, row “…” menus; enables bulk QR.
  5. Complete the asset sheet — photo, commissioning date, Preventive tab, decommission / delete, real QR with PNG and label formats.
  6. Home operational layer — alert cards, reminders, operational KPIs, period / filters; answer “customizable” with role-based presets.
  7. Meter readings on assets — makes “every 500 h” plans work and is the first brick of condition-based maintenance.
